# ADR 0004: First runtime integration reads ONNX Runtime profile files

Status: accepted (M4)

**Context.** The MVP needs one honest, reproducible runtime integration. Hooking into a runtime's kernels means linking it and tracking its internal APIs.

**Decision.**
- Parse the Chrome-trace JSON that ONNX Runtime writes with `EnableProfiling`, tested on 1.20.1.
- `llm-trace` does not link ONNX Runtime. The optional `onnx_profile_runner` example does, and it produces profiles and measures their overhead.
- The tiny model is generated by a script from seeded random weights, so it can be redistributed.

**Consequences.**
- Inspection is offline (after the run), not live.
- Profiling overhead belongs to ONNX Runtime, is measured by the runner, and is reported per workload.
- Live capture through a runtime hook is future work.
